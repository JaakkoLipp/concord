# M4.8 plan: everyday usability

Status: draft for Jaakko's sign-off, revised after a Sonnet challenger review. Implements the M4.8 section of [milestones.md](milestones.md). Built from a Sonnet audit of the client on 2026-10-16, with line references to the code as it is on `main`. Results go in `docs/m4.8-results.md`.

Working agreement, as in M4.5:
- Each finished task is committed and pushed after `pnpm verify`, run right before the commit. Agents work on the local stack at `http://localhost`.
- Production's `/app` is deployed at the three review points below, then checked with `routes.ts`.
- Implementation is done by **Haiku subagents, one at a time, in the main checkout** (see "How the work is done"). The main session briefs, reviews, verifies, commits and deploys.

## What Stoat gives, and what it doesn't

| Item | State in 0.15.5 |
|---|---|
| First unread | Only `last_id` per channel and the unread mention IDs. **No count of unread messages.** |
| Account | Every route exists: password, email, sessions, TOTP, recovery codes. `GET /auth/session/all` returns only `_id` and `name`, no last-seen. Some routes need an `x-mfa-ticket` header (probe 1b). |
| Server order | Stoat's `ordering` setting holds `{servers: [ids]}`. Its own client writes it too. Nothing in ours writes it yet. |
| Search | One channel at a time, `query`, `before`, `after`. **No author field**, so "from someone" is a client-side filter. |
| Notes on people | No route. Our own `concord:notes` setting, as client.md line 206 already says. |
| Mentions | Cold-start `mentions` don't say why a message counted, so @everyone and role mentions can't be filtered after a reload. |

**Shared files.** Nearly every task touches `i18n/en.ts`, `session.svelte.ts` or `Shell.svelte`, which is why agents run one at a time. M4.7 (worktree `m4.7`) edits `en.ts`, `Shell.svelte`, `session.svelte.ts` and both `backend.ts` files too, so these are named in each task's Files and we rebase carefully (see "Coordination").

## How the work is done

- **One Haiku agent per task, one task at a time**, in the main checkout.
- **Each brief stands alone**: the task text and its done-check, the files and line references, the six-step `concord:` recipe where it applies, and the rules: no literals (`m.*` strings), tokens only, the motion rules of client.md section 9, no new dependency, no commit or deploy, no `seed --reset`, none of M4.7's files outside the list, `pnpm verify` passing before it returns, and a list of the files it changed.
- **The main session owns** the review of the diff, a second `pnpm verify`, the live check, the commit and push, and the deploy.
- **Risky tasks**, reviewed line by line: 4 (opening at the first unread), 8 and 9 (My Account with MFA) and 10b (folder sync). If Haiku fails one of them once, it goes to a Sonnet agent.
- **Live checks** are new files in `tools/live/src/`, named in each task. They run as `node tools/live/src/<name>.ts`, like the existing ones. The headless browser can't hear sounds, so the sound check injects a spy on `createOscillator` with `addInitScript`.
- **The `concord:` recipe**, which the briefs point to. A new synced key follows `GIFS_KEY`, in `packages/domain/src/session.svelte.ts` (`:75-78`, `:710-712`):
  1. a `*_KEY` constant and a `parseX` function that tolerates bad data and caps its size,
  2. the key in the explicit list in `coldStart` (Ready carries no settings),
  3. a branch in `settingsChanged`, guarded by the saving flag or timestamp so our own echo doesn't undo a newer local change,
  4. a debounced save through `backend.setSettings`, with `Latest` and `HOLD_MS`,
  5. a field on `Store`, and its reset on sign-out,
  6. a unit test next to it.

  Writes to Stoat's own `ordering` key merge into the raw stored JSON, because `parseSettings` drops fields it doesn't know and Stoat's own client writes the key too.
- A Sonnet agent reviews the session's whole diff before each review point.

## Decisions made in this plan (recommended defaults)

- **Shortcuts**: one registry, `apps/web/src/lib/shell/shortcuts.ts`, holding `{id, keys, label, run}`. It feeds one capture-phase window listener in `Shell.svelte` and the Ctrl+/ list.
  - Ctrl+K gets `preventDefault`, since Firefox uses it.
  - Shortcuts are ignored while a dialog, menu, popover or picker is open.
  - The voice keybind recorder refuses any key the registry owns.
  - **Esc is the trap.** Many things already use it: the composer (cancel a reply, else mark read), the find box, the edit box, incoming calls, autocomplete, the image viewer, the keybind recorder and the settings frame. The rule: the global Esc acts only if the event target isn't an input, textarea or contenteditable, isn't inside a dialog, `defaultPrevented` is false, and no menu, popover or picker is open.
  - **The registry stays silent while a keybind is being recorded**, so Ctrl+K can't open the switcher mid-recording.
  - **Ctrl+Alt+Up and Down** may be taken by the OS on some desktops. Jaakko tests them on Windows and Linux. If either eats them, every shortcut gets a second binding with Shift added, decided then.
- **Keyboard-opened overlays don't animate** (client.md section 9, rule 2). `Dialog.svelte` honours `fromKeyboard()` through a still mode.
- **Opening at the first unread**:
  - If the whole unread run is in the loaded window, the bar says the exact count. Otherwise it says "since <time>".
  - A channel opened mid-history becomes read when the user scrolls to the bottom, presses Esc, or clicks the bar's button.
  - A `[[message]]` jump and a held "Mark unread" take precedence over opening at the unread.
- **Mentions inbox**: unread mentions only, as a to-do list. It fetches message bodies with a new `Backend.message` (`GET /channels/{c}/messages/{id}`, which probe 0 confirms).
- **Ignoring @everyone and role mentions** hides them everywhere: notifications, sounds, badges and inbox rows. Counts delivered at cold start can't be filtered.
- **Server order and folders**:
  - Stoat's `ordering` stays the order of servers. Writes merge into the raw stored JSON and keep unknown fields.
  - `concord:folders` is `{folders: [{id, name, color?, servers: [ids]}]}`. The rail order is `ordering`, with a folder shown at the position of its first server.
  - Dropping a server on a tile makes or joins a folder, and dropping between tiles reorders. A server the user has left is dropped from its folder when the folders are read. A folder left with one server dissolves.
  - Ctrl+Alt+Down steps through servers in rail order, into a collapsed folder's first server.
  - Two devices write last write wins, per key, with the hold logic from the recipe.
  - Dragging uses native pointer events, no library. The dragged tile moves by `transform` only, and the list does not animate.
  - Move up and Move down in `serverMenu` are the keyboard path, as `moveChannel` is for channels.
- **Drafts**: localStorage per account, capped in size, written on a debounce and on `pagehide`, wiped in `signedOut()`. Today the text is stored only on a channel switch, so a reload while typing loses it.
- **Collapsed categories**: per device, in localStorage, per server.
- **"From someone"**: keeps loading pages until it has a page of matches or runs out, and says "searched N messages" when it stops. A client-side filter would otherwise show empty pages while matches exist further back.
- **Ignoring @everyone and role mentions per server**: its own `concord:mentions` key. Counts delivered at cold start can't be filtered after a reload, and the settings page says so.
- **Message sounds**: played by the leader tab only, never for the channel in focus, and independent of desktop-notification permission.
- **Session names**: login sends a per-device friendly name such as "Concord on Chrome, Windows", and stores the session ID, so the list can mark "this device".

## Tasks

### 0. Probes

On the local stack. Use a fresh persona from `pnpm seed account …`, never `--reset`. Remove any TOTP added. Each answer goes in m4.8-results.md before the task that depends on it is briefed.

- **Banner timing**: does Playwright's `setOffline(true)` close an open socket, and how long until the state is `reconnecting`? This decides whether the banner needs a `window` `offline` listener, or shorter ping and pong times.
- **MFA**: which of password change, email change, session revoke, TOTP enable and disable, and recovery codes need `x-mfa-ticket`? Is a ticket single-use? Does a password change log out the other sessions?
- **Voice messages**: does Autumn classify an audio-only WebM or Ogg upload as Audio or as Video?
- **CodeMirror**: does its keymap bind Ctrl-Alt-Arrow?
- **Cold-start mentions**: do DM and group `mentions` match the live `mentionsSelf` rule?
- **Single message fetch**: does `GET /channels/{c}/messages/{id}` return one message with its author?
- **Email change**: on the local stack (Mailpit) and, read-only from the runbook and config, on production, which has no SMTP: does it apply at once, need a verification mail, or fail? This decides whether the form is shown on production or left to M6.
- **Tokens already stored**: a signed-in browser has no session ID. Does `GET /auth/session/all` let us match its token to a session, or does "This device" need a fallback (the newest session by name)?

**Done when** each has an answer, and the tasks that depend on one are adjusted.
