# M4.6 results: UI motion and design parity

Jaakko approved the plan and all 13 decisions on 2026-10-16. Commands and browser checks run in WSL. Implementation is isolated from the parallel M4.7/M4.8 checkout.

## 0. Probes

- **Settings:** a shallow push to the settings URL keeps the underlying shell mounted. Back closes it without calling `beforeNavigate`; dirty Back must restore the entry and ask directly. A tested opener sequence navigates to the base route before pushing settings. Reload currently reaches the standalone route, so task 16a must turn the three routes into openers over the remembered channel. See [settings probe evidence](m46-settings-probes.md) for tested behavior and the keyboard audit.
- **Zero durations:** Chromium and Firefox both close the real custom-status dialog after its zero-duration Svelte outro. Its `onoutroend` callback runs. A bare zero-duration WAAPI animation is already finished and absent from `getAnimations()` immediately and on the next frame. The live recorder must inspect computed timings and permit animations that never enter that list.
- **Scrollbars:** both engines compute a transparent thumb initially and while hovering the parent outside the child, then a coloured thumb over the child scroller. Use the standard `scrollbar-color` hover rule in both engines; avoid competing prefixed thumb colours. Headless checks read computed style; Jaakko's final recording checks painted shape and visibility. See [motion probe evidence](m46-motion-probes.md).

Reproduced with `node tools/live/src/probes/m46-motion.ts` and `PROBE_BROWSER=firefox node tools/live/src/probes/m46-motion.ts`. Firefox is a user-cache Playwright runtime; no system packages were installed. The disposable settings branch is removed after the probe.

## 1. Tokens, rules and lints

Added the spec’s timings, curves, modal radius and separate profile, side-panel and preview widths. Renamed `--dur-hover` to `--dur-state`; floating menus, popovers and dock use 8 px corners. Syntax and video colours now come from tokens. Section 9 and the accessibility rule in client.md follow M4.6.

`pnpm verify` includes the new CSS colour lint. A temporary component containing a planted hex, rgb and hsl fails; an ID selector and a `name#1234` string pass. The motion lint permits grid rows only on SettingsFrame’s `.subnav`. The colour-transition ban lands with task 3, as planned.

## 2. Reduced motion

All duration tokens become zero under reduced motion, with the spinner’s independent 1.8 s token preserved. Message jumps show a static highlight for 2 s, then clear. The recorder now reads computed duration and active duration; content-retention assertions run only in normal mode.

Local `MOTION_MODES=reduce node tools/live/src/motion.ts` passed, including dialogs closing and returning focus, both quick menus, settings, image viewer, voice panel, tile joins/leaves and the static highlight’s expiry. No positive animation duration was recorded. Spinner and spring checks arrive with tasks 15 and 5/17.

## 3. Instant hover

Removed hover fades from buttons, icon buttons, rail tiles, call controls and GIF stars; press scales and speaking rings remain. The motion lint rejects colour transitions except the explicitly named toggle tracks, including a planted hover colour transition.

The five hover checks passed in normal and reduced modes. A full normal-mode motion run on the isolated local preview also passed; an earlier cold run recorded two frame stalls while loading the picker and settings.

## 4. Tooltips

Tooltips use separate nodes, start on the first hover frame and crossfade in 100 ms without scale. They have the floating surface, caret, 8 by 12 px padding and semibold text. Rail tooltips sit right, show a bold name and a translated Muted line; close buttons in both side panels sit below. Removed targets clean up their tooltip immediately.

`parity.ts` passed: gear, rail, find-panel and voice-chat close placements, full opacity in 98–114 ms, overlapping nodes during crossfade, target-removal cleanup and zero-motion reduced mode. The full motion check passed in both modes on the isolated preview.

## 5. Spring scroll

Added a per-scroller critically damped spring at 12.75 rad/s. It uses the analytic position and velocity so dropped frames do not stretch time, preserves both on retarget, cancels on wheel/touch and jumps under reduced motion. Scroll-spy can query whether a spring is running.

Unit tests check 600 and 1,200 px moves reaching 99% within 490–550 ms and continuity when reversing target mid-scroll. Task 17 measures the actual settings scroll in the browser.

## 16a. Settings over a mounted shell

`openSettings()` in `settings/modal.svelte.ts` replaces the five `goto` openers: the dock's gear and its Voice settings item, Edit profile, and the server and channel settings openers in `admin/menu.ts`. It pushes the unchanged settings URL as shallow state, and `SettingsHost` in the channels layout draws the modal from it, so the shell, the call and the conversation stay mounted. The three settings routes are now openers: they go to the last channel, or one in that server, then open settings over it. Section links switch in place with `replaceState`, so Back and Esc close settings in one step; a modified click still opens the URL.

- **Unsaved changes**: the five guarded editors register with the modal through `guardUnsaved`, which keeps `beforeNavigate` for real navigations and closing the tab. Closing, a section switch and a shallow Back ask first; on Back the modal pushes its entry again and asks, and Leave goes back.
- **Under the modal**: the shell's overlay hosts (toasts, confirm, menus, emoji picker, image viewer, admin and moderation dialogs, mentions, incoming calls) moved out of `.shell`, which goes inert. Incoming calls sit above settings. Settings' own confirm, toaster and member dialogs are gone. The profile popout closes on open. Focus returns to the opener, or to the menu button when a menu item opened it.
- **Window key handlers gated while settings is open**: Shell's one capture listener, which runs M4.8's shortcut registry (all its entries, including Ctrl+/ and Ctrl+K) and type-to-focus; the dock's mute and deafen keys; the composer's Ctrl+E. The context-menu key's capture listener only records the key, and the inert shell gets no contextmenu event. Voice settings' recorder keeps its capture priority, and the mic test's push-to-talk key stays live, since it belongs to settings. Esc closes settings from a bubble listener, after menus and popovers have taken theirs, and not while a native dialog is open.
- At 800 px or less settings stays full-screen, as now; task 16b insets it above that.

A new section of user settings is a name in `USER_SECTIONS` and a branch in `Settings.svelte`; `SettingsFrame` items take a target instead of an href.

`tools/live/src/settings-modal.ts` covers the done-check: each kind opened by clicking during a call, the same call and conversation elements and scroll on close, Esc, Back and X, Esc closing a menu in settings first, the unsaved-changes question on Back, focus back on the gear, Tab staying out of the shell, Ctrl+E and Ctrl+Shift+M inert, recording Ctrl+Shift+M without muting, a reload reopening settings, and phone width. `pnpm verify` passes. The first local run found the unsaved-changes Back failing: the shown target was a `$state` proxy, which history state can't clone, so it is now `$state.raw`. `settings-modal.ts` then passed in full on the isolated preview, with the conversation scrolled 5,099 px up and the same elements and scroll after each close.

## 6. Rail pill

The pill is 40 px tall, clipped to 8 px for unread, 20 on hover and 40 when selected. A hovered selected server keeps 40 px: the selected rule now comes after hover with equal specificity. Growing, it slides in from the left and fades up over `--dur-pill-in` (200 ms) on the spec's standard curve; shrinking takes `--dur-pill-out` (100 ms). Rail tooltips are task 4's.

`parity.ts` gains the pill step: the home icon's pill from hidden to 20 px with clip, slide and fade transitions at 200 ms and back at 100 ms, the selected server at 40 px hovered or not with no transition, and an unread server at 8 px growing to 20 in 200 ms and back in 100 ms. `pnpm verify` passes. Run locally with task 7: all pill steps passed, with transitions recorded at exactly 200 and 100 ms.

## 7. Channel row actions

Each channel row is now a row holding its link and, beside it, Invite to channel, Edit channel and, on voice channels, Open chat, each with its tooltip above. They show on a hovered or selected row, or when the row has keyboard focus, and only with a hover pointer; on touch the context menu stays the way in. `channelActions()` in `admin/menu.ts` gives the menu and the buttons the same permission checks. Edit opens channel settings through 16a; Open chat opens the voice channel with its chat, without joining. The hover and selected backgrounds moved to the row, and hovered text steps up: normal to `--text-strong`, muted to `--text-secondary`. M4.7's lock on voice channels without Connect is kept.

`parity.ts` passed in full on the isolated preview with tasks 4, 6 and 7: `dev` sees no Edit channel and no Invite, matching their menu; `dev-admin` sees Invite and Edit on #yleinen and Open chat, Invite and Edit on Olohuone; the tooltip is above; Invite opens the invite dialog, Edit opens channel settings, and Open chat shows Olohuone with its chat and no call. `motion.ts` passed in both modes; its settings-close step now allows the gear's tooltip, which shows because Esc returns keyboard focus to it. `gifs.ts` ran first to give motion.ts a GIF after the reseed.

## 8. Message action bar

The bar is on `--surface-1`, 32 px tall: the top three of M4.5's use-ranked quick reactions, a divider, Add reaction, then Edit on one's own message or Reply on others', and More. Reply on one's own messages stays in the menus.

`parity.ts` passed: on a fresh message from `aino`, the bar measures 32 px on the token's colour, reads three reactions, divider, Add reaction, Reply, More, and the first reaction lands on the message (then removed). `motion.ts` passed in both modes.

**Checks now run on a built preview** (`vite build`, then `vite preview --port 5196`). Under `vite dev`, the reaction list's `?raw` import is served as `text/plain` and every reaction fails, in the menu as well as the bar; the build inlines it, so it doesn't reach `/app`.

**Log out from settings**, two bugs from 16a: Profile's editor threw when the account went before the modal, so Log out now closes the modal first (`settingsModal.dismiss()`); and the members fetch that `openServer` starts, now running under settings after a reload, could reject with a 401 at logout uncaught, so it is caught as the refreshes already were. `settings-modal.ts` gains a Log out step and passed in full on the build.
