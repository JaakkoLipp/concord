# M4.6 results: UI motion and design parity

Jaakko approved the plan and all 13 decisions on 2026-10-16. Commands and browser checks run in WSL. Implementation is isolated from the parallel M4.7/M4.8 checkout.

## 0. Probes

- **Settings:** a shallow push to the settings URL keeps the underlying shell mounted. Back closes it without calling `beforeNavigate`; dirty Back must restore the entry and ask directly. A tested opener sequence navigates to the base route before pushing settings. Reload currently reaches the standalone route, so task 16a must turn the three routes into openers over the remembered channel. See [settings probe evidence](m46-settings-probes.md) for tested behavior and the keyboard audit.
- **Zero durations:** Chromium and Firefox both close the real custom-status dialog after its zero-duration Svelte outro. Its `onoutroend` callback runs. A bare zero-duration WAAPI animation is already finished and absent from `getAnimations()` immediately and on the next frame. The live recorder must inspect computed timings and permit animations that never enter that list.
- **Scrollbars:** both engines compute a transparent thumb initially and while hovering the parent outside the child, then a coloured thumb over the child scroller. Use the standard `scrollbar-color` hover rule in both engines; avoid competing prefixed thumb colours. Headless checks read computed style; Jaakko's final recording checks painted shape and visibility. See [motion probe evidence](m46-motion-probes.md).

Reproduced with `node tools/live/src/probes/m46-motion.ts` and `PROBE_BROWSER=firefox node tools/live/src/probes/m46-motion.ts`. Firefox is a user-cache Playwright runtime; no system packages were installed. The disposable settings branch is removed after the probe.

## 1. Tokens, rules and lints

Added the spec’s timings, curves, modal radius and separate profile, side-panel and preview widths. Renamed `--dur-hover` to `--dur-state`; floating menus, popovers and dock use 8 px corners. Syntax and video colours now come from tokens. Section 9 and the accessibility rule in client.md follow M4.6.

`pnpm verify` includes the new CSS colour lint. A temporary component containing a planted hex, rgb and hsl fails; an ID selector and a `name#1234` string pass. The motion lint permits grid rows only on SettingsFrame’s `.subnav`. The colour-transition ban lands with task 3, as planned.

## 2. Reduced motion

All duration tokens become zero under reduced motion, with the spinner’s independent 1.8 s token preserved. Message jumps show a static highlight for 2 s, then clear. The recorder now reads computed duration and active duration; content-retention assertions run only in normal mode.

Local `MOTION_MODES=reduce node tools/live/src/motion.ts` passed, including dialogs closing and returning focus, both quick menus, settings, image viewer, voice panel, tile joins/leaves and the static highlight’s expiry. No positive animation duration was recorded. Spinner and spring checks arrive with tasks 15 and 5/17.

## 3. Instant hover

Removed hover fades from buttons, icon buttons, rail tiles, call controls and GIF stars; press scales and speaking rings remain. The motion lint rejects colour transitions except the explicitly named toggle tracks, including a planted hover colour transition.

The five hover checks passed in normal and reduced modes. A full normal-mode motion run on the isolated local preview also passed; an earlier cold run recorded two frame stalls while loading the picker and settings.

## 4. Tooltips

Tooltips use separate nodes, start on the first hover frame and crossfade in 100 ms without scale. They have the floating surface, caret, 8 by 12 px padding and semibold text. Rail tooltips sit right, show a bold name and a translated Muted line; close buttons in both side panels sit below. Removed targets clean up their tooltip immediately.

`parity.ts` passed: gear, rail, find-panel and voice-chat close placements, full opacity in 98–114 ms, overlapping nodes during crossfade, target-removal cleanup and zero-motion reduced mode. The full motion check passed in both modes on the isolated preview.

## 5. Spring scroll

Added a per-scroller critically damped spring at 12.75 rad/s. It uses the analytic position and velocity so dropped frames do not stretch time, preserves both on retarget, cancels on wheel/touch and jumps under reduced motion. Scroll-spy can query whether a spring is running.

Unit tests check 600 and 1,200 px moves reaching 99% within 490–550 ms and continuity when reversing target mid-scroll. Task 17 measures the actual settings scroll in the browser.
