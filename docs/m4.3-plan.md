## What Stoat gives, and what it doesn't

From `packages/stoat/api/0.15.5/openapi.json` and `packages/stoat/src/`.

| Item | State in 0.15.5 |
|---|---|
| Search | **One channel per request**, `POST /channels/{c}/search`. **No author, attachment, link or mention field, and no server-wide route.** |
| Search parameters | `query` is 1 to 64 characters, MongoDB text search, so whole words. `pinned` can't go with `query`. `limit` is 1 to 100, and there are `before`, `after` and `include_users`. Without `query`, every message comes back. |
| Search sort | `Relevance`, `Latest` or `Oldest`. The schema's default is `Relevance`, while its text says Latest. **No score comes back**, so relevance can't be merged across channels. `Session.search` forces `Latest` and re-sorts newest first (`session.svelte.ts:1399-1403`). |
| Reactions | `Message.reactions` maps each emoji to **every user ID**, so who reacted needs no new route. The tooltip cuts at six (`conversation/Reactions.svelte:21`). |
| Interactions | A message's `interactions` has `reactions` (always shown) and `restrict_reactions` (only those allowed). Concord maps neither (`packages/domain/src/backend.ts:150-154`). Keycaps 1️⃣ to 🔟 are in Stoat's emoji list. |
| Custom status | `UserStatus` is `text` (up to 128) and `presence`. **No expiry.** |
| Role icon | `DataEditRole.icon` takes an Autumn file ID, and `FieldsRole` has `Icon` for removal. **Concord drops it**: there is no `Role.icon` (`packages/domain/src/entities.ts:51-60`), the mapping ignores it (`packages/stoat/src/map/server.ts:5-7,51-59`), and a role `remove` always sends `Colour` (`packages/stoat/src/backend.ts:458`). Icons show nowhere today; the research was wrong to say the profile card shows them. |
| Owner transfer | `DataEditServer.owner` on `PATCH /servers/{c}`. The file lists the session token and `x-mfa-ticket` only as alternatives, so the need for a fresh ticket rests on m2c-plan.md's probe. Tickets are single use (m4.8-results.md probe 2). `ServerEdit` has no `owner` (`packages/domain/src/backend.ts:196-206`). |
| Attachment name | `File.filename` is "Original filename". The upload sends the name it is given (`packages/stoat/src/backend.ts:392-399`), which is `c.file.name` today (`shell/Composer.svelte:148`). |
| Category mute | Stoat's `notifications` key knows servers and channels only. A category is `id`, `title` and `channels`. |

## Decisions made in this plan (recommended defaults)

1. **Settings**:
   - Reduced motion, GIFs and animated emoji go in a new **Accessibility** section.
   - Previews, reactions and spoilers go in a Chat group in **Appearance**.
   - Streamer mode gets its own section.
   - The **existing Keybinds list** in Voice and video grows to every shortcut, as the milestone says.
   - All of it is per device, as Appearance is.
2. **Reduced motion**: **Follow my system** is on by default. One root attribute, `data-motion="reduce"`, replaces the media query everywhere, so the in-app switch and the OS setting give the same result by construction.
3. **GIFs and emoji**:
   - **Play GIFs automatically** is on by default. Off, a still shows until hovered or focused.
   - **Animated emoji**: Always (default), On hover, or Never.
   - **The still** is Autumn's resized URL if probe 6 says it's static. Otherwise the first frame is drawn on a canvas. No new dependency.
4. **Previews off** hides embeds, or shows images and videos as file cards. **Reactions off** hides the chips, except on a vote.
5. **Spoiler reveal**:
   - **On click** is the default.
   - **In servers I moderate**: uncovered where I have Manage messages.
   - **Always**.

   It covers text and files. Streamer mode forces On click. This replaces the milestone's "on hover" (question 1).
6. **Spoiler files** are named `SPOILER_…`.
   - **Before reveal**, a covered file renders no `<img>`, `<video>`, `<audio>`, `data-original`, file name or `download`. The cover is a blurred thumbhash, or a flat cover for videos and files.
   - **Spoilered links**: an embed is covered unless its URL is also in the text outside a spoiler, so the check fails closed.
   - **Reveals last** only while the message is shown.
7. **Status "clear after"**:
   - **The choices**: 30 minutes, 1 hour, 4 hours, Today or Don't clear. **The default is Today.**
   - **The key**: `concord:statusExpiry` holds `{text, until}`.
   - **The clearer** is one tab: whichever holds the existing idle lock (`session/idle.ts:47`), whether or not notifications are on. It clears **only if a fresh fetch shows both Stoat's status text and the stored record unchanged**.
   - Any status change rewrites or deletes the record.
   - Accepted: a status set in the moment between that fetch and the clear, and a device clock that runs fast.
8. **Category mute**:
   - **The key**: `concord:categoryMutes`, per `server/category`, with a channel mute's durations. Writes merge entry by entry, as notes do, so two devices muting different categories both keep theirs. Entries for deleted categories drop on read.
   - **The effect**: `Store.isMuted` reads it, so everything that follows mutes follows it, including channels added to the category later.
   - **Not seen by** Stoat's own client and M7's push.
9. **Apply to category**: copies one override (Everyone's or a role's) to the category's other channels.
   - **It replaces** that entry's allow and deny there.
   - **Every channel where it would grant something new is unticked and marked**, and View channel is marked loudest.
   - There is no undo.
10. **Server search**:
    - **The default** is This server, with This channel and In #channel. DMs stay per conversation.
    - **Which channels**: text channels with View channel and Read message history, and age-restricted ones only once confirmed on this device. **At most 50, 4 at a time.** Searching the rest restarts the merge with them included.
    - **Order**: newest first, or oldest. **Relevance** only for one channel.
    - **Coverage**: the panel names what it searched and what it skipped, and why (age-restricted, over the cap, refused, failed).
11. **Has and mentions** are controls beside From and the dates, not typed operators.
    - Without a query they scan within a budget per click: 10 pages per channel, 3,000 messages in all. The channel with the newest unscanned messages goes next, so no channel eats the budget.
    - Mentions matches direct mentions only.
12. **Who reacted**: a click still toggles, as on Discord. The list opens from a chip's menu or **Reactions** in the message menu (question 2).
13. **Votes**:
    - **The message**: `📊 **Question**` and up to ten `1️⃣ Option` lines, sent with those keycaps as `interactions` and `restrict_reactions` on.
    - **Results**: bars, live from the reactions.
    - **Restricted reactions**: Concord offers no other reaction on such a message.
    - **The label**: "Informal vote: any number of choices, everyone sees who voted, no end time."
14. **The cropper**:
    - **Output**: squares at 512 px, banners at their shown ratio at 3 times its size, as PNG through a canvas, which drops EXIF data. The size is checked again after cropping.
    - **Animated GIF, WebP and APNG files**, found by their headers, skip it.
15. **Role icons** show beside names in chat and the member list, from the highest-ranked role that has one. The profile card is left to M4.9.
16. **Owner transfer**: the owner only.
    - **Confirming**: a dialog with a tick box, then a fresh ticket.
    - **Afterwards**: the layer's 30 s permission cache (`server/layer/layer.ts:144-160`) means the old owner keeps layer rights briefly. That is accepted.
17. **Keybinds**:
    - Every registry shortcut can be rebound, per device, in `concord:keybinds`.
    - A key owned by another shortcut, or by mute, deafen or push-to-talk, is refused.
    - Esc and typing into the composer stay fixed.
18. **Streamer mode**:
    - **Turning it on**: a switch, an unbound keybind as on Discord, and **"Turn on while I share my screen"** (on by default). The flag sits in localStorage, so every tab sees it.
    - **What it hides**:
      - email;
      - the two-factor secret and recovery codes;
      - invite links and codes;
      - beta invitations, with their emails and links;
      - one-time password links;
      - private notes.
    - **What it silences**: **every** desktop notification, including the call ring, which is stricter than the milestone's "contents". Every app sound is off too. Call audio isn't touched.
    - **Spoilers**: on, it forces On click and closes open reveals.
19. **Badges**: `setAppBadge` with the title's count where it exists, which lights up once M7 makes the app installable, and a dot on both favicon links.
