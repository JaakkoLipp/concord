# M4.2 results

Plan: [m4.2-plan.md](m4.2-plan.md). Signed off on 2026-10-15 with Jaakko's direction: Discord's style, slight, polish only. Built the same day on the local stack.

## What moves now

| Surface | Enter | Exit |
|---|---|---|
| Menus, popovers, emoji picker | fade and 0.98 scale from the trigger, 150 ms | fade and shrink, 100 ms, keeping their content |
| Opened from the keyboard | nothing | nothing |
| Tooltips | fade and 0.98 scale from the side facing the element | fade, 100 ms. A neighbour's shows at once, without motion |
| Dialogs, image viewer | fade and 0.98 scale, backdrop fades, 200 ms | both fade, 100 ms, then the native close |
| Settings | fade, 200 ms | instant |
| Voice panel | fade and a 4 px rise, 200 ms | fade, 100 ms |
| Call tiles | someone joining: fade and 0.98 scale | someone leaving: fade and shrink |
| Toasts, incoming call cards | fade and a 4 px drop, 200 ms | fade, the others slide up |
| Buttons, call controls | pressed: 0.98 scale | |
| Speaking rings, ringing pulse, rail pill | opacity or scale only, no `box-shadow` or `height` | |

New messages, channel switches and keyboard-opened surfaces don't move.

**Reduced motion**: `--motion` is 0, so every scale and movement collapses and the fades stay. The drawer, toggle knobs, chevrons and the rail pill snap. The typing dots and ringing pulse stop.

**Hover**: the 50 hover rules that only change colour apply to fine pointers only, through `@media (hover: hover)`. The 16 that reveal controls, such as a message's action bar, are unchanged, so touch still reaches them. Tooltips answer a mouse only.

## Checks

- `tools/lint/motion.ts`, in `pnpm verify`, fails on anything but `transform`, `opacity` and colours animating, on raw durations and curves outside tokens.css, and on `transition: all`. It caught the `background` shorthand, which also animated the background's position.
- `tools/live/src/motion.ts` opens every surface above with reduced motion off and on, with `aino` joining and leaving a call. It records every CSS and Svelte animation and passes:
  - only the allowed properties change, and only opacity and colours under reduced motion,
  - closing menus and dialogs keep their content,
  - keyboard-opened menus and settings' section changes don't animate,
  - the first tiles and a grid-focus switch don't animate, while joins and leaves do,
  - no frame where something animates exceeds 50 ms.

**The emoji picker's first open** in a session takes 280 to 330 ms of image decoding in headless Chromium, which has no GPU. Rendering only its first view with the animation and the rest a few rows a frame later moved that cost after the animation, from about 600 ms before it. Later opens run at 17 ms frames. Jaakko's performance recording on the reference machine decides whether the first open needs more.

**Not checked by script**: toasts and the incoming call card, which need a failure or a DM call to appear. The lint covers their CSS. Firefox wasn't run. Dialogs there may lose the backdrop's fade, which `dialogLeave` allows for.

## Observed on the local stack: Stoat's voice state broke again

During the check's development, voice-ingress began answering every LiveKit webhook with 500, and nobody showed in a call though both clients were connected. This is the missing-room-metadata failure from M4 task 9. Restarting LiveKit cleared it.

It followed a run where `aino`'s page was reloaded after leaving a call and then rejoined. Simply rejoining, with or without a pause, didn't reproduce it. The check now signs `aino` in fresh for each pass and passes reliably.

It isn't understood yet. It adds to decision gate criterion 5's evidence and is one more thing for the voice evening to watch.
